# Feature list

## Purpose
`docs/FEATURES.md` is one generated file per repo that lists every feature
with its lifecycle state: what ships, what is being built, what is queued,
what is being retired and what was removed. Agents read it before proposing
a PRD or answering what exists; the owner scans it at a glance. It is never
edited by hand: `features.sh` derives it from the files that already hold
the truth (specs, open PRDs, the `## Next` table, the archive), so it
cannot drift. It does not replace the specs or PRD indexes and carries no
dates or ETAs for planned work.

## Behavior
1. **Command.** `features.sh [--check|--json] [repo]`, in
   `claude-home/skills/implement-prd-section/scripts/` (global, next to
   `state.sh` and `prd-lint.sh`); repo defaults to the git top level.
   - Write mode renders `docs/FEATURES.md` and prints
     `features.sh: docs/FEATURES.md written|unchanged (<n> rows; <counts>)`.
   - `--check` writes nothing; exit 1 with
     `docs/FEATURES.md: stale, run features.sh` when the file is missing or
     differs from a fresh render.
   - In a shallow clone, spec dates are unknowable: `--check` exits 1 with
     `docs/FEATURES.md: shallow clone; spec dates need full history
     (actions/checkout fetch-depth: 0)` and write mode exits 2. The
     template's CI checks out with `fetch-depth: 0`.
   - `--json` prints the rows as a JSON list of
     `{feature, state, what, spec, change, updated}`.
   - Neither `docs/specs/` nor `docs/prd/` → exit 2 with a message.
2. **File shape.** Line 1 `# Features`; line 2
   `<!-- generated by features.sh from docs/specs, docs/prd, docs/prd/archive; do not edit -->`;
   line 4 the counts (`2 building · 1 pinned · 0 deprecated · 3 planned · 9 shipped · 1 removed`);
   then `| Feature | State | What it does | Spec | Change | Updated |`.
3. **Sources.** Specs are `docs/specs/*.md` minus README. Open PRDs are
   `docs/prd/*.md` minus `README.md`, `migration-plan.md`, `repo-setup.md`
   and `research-*.md`; Status `SUPERSEDED` or `DROPPED` is not listed. A
   PRD's delta is its top-level `## Spec delta` bullets
   `- ADDED|MODIFIED|REMOVED \`docs/specs/<x>.md\``; a REMOVED bullet is
   whole-file when no `§` precedes its first `:`.
4. **States** (derived, never typed):
   - BUILDING: an open PRD with Status `BUILDING` or any `[x]`/`[~]`
     Sections item.
   - Per existing spec, precedence DEPRECATED > BUILDING > PINNED >
     SHIPPED: DEPRECATED when an open PRD has a whole-file REMOVED for it;
     BUILDING when a BUILDING PRD names it; PINNED when another open PRD
     names it or a `## Next` row targets it; else SHIPPED.
   - A PRD gets its own row (BUILDING, else PLANNED) when it ADDs a spec
     that does not exist yet or names no existing spec.
   - A `## Next` row targeting `new` (or a missing spec) is PLANNED.
   - REMOVED: an archived PRD with Status `SHIPPED` and a whole-file
     REMOVED for a spec that no longer exists; newest 10 archive files.
5. **Cells.**
   - Feature: spec stem; a PRD's own row: PRD stem; a Next row: the idea
     as lowercase kebab, ≤40 characters.
   - What it does: the specs index Capability cell, else the PRD H1 title
     without ` — PRD`, else the idea text; whitespace collapsed, `|`
     escaped, cut to 60 characters with `…`.
   - Spec: `[spec](specs/<x>.md)` or `-`.
   - Change: `[<prd>](prd/<prd>.md) <done>/<total>` from `[x]` Sections
     items, or the Status word without a `Sections:` list; several PRDs
     → the first deciding one by name plus ` +<m>` others; `Next #<n>`;
     a REMOVED row links its archive file; else `-`.
   - Updated: the deciding PRD's `Last updated` (latest of several), else
     today when the spec has uncommitted changes or is untracked (the date
     its commit will carry, so a pre-commit run stays current), else its
     last commit date, else `-`; REMOVED: its SHIPPED date.
6. **Order.** BUILDING, PINNED, DEPRECATED (each by name), PLANNED (Next
   order, then PRDs by name), SHIPPED by name, REMOVED newest first.
7. **Size.** Over 60 rows: the file is still written, write mode prints and
   `--check` fails with `docs/FEATURES.md: over 60 rows; group specs or trim`.
8. **`## Next`** in `docs/prd/README.md`, after the index:
   `| # | Idea | Targets | Notes |`, ≤10 rows in intended order; Targets is
   an existing spec stem or `new`. Writing the PRD deletes its row in the
   same commit; dropping an idea deletes it.

## Data & contracts
- `docs/FEATURES.md`: generated markdown, shape in Behavior 2.
- `docs/prd/README.md` `## Next` table.
- `features.sh` exit codes: 0 ok, 1 `--check` failed, 2 no docs dirs or
  a shallow clone in write mode.
- Tests: `scripts/quiet-check.sh features`
  (`claude-home/skills/implement-prd-section/tests/features_test.sh`).

## Invariants (regression checklist)
- [ ] A second run on the same tree prints `unchanged` and the file is
      byte-identical.
- [ ] `--check` never writes.
- [ ] Each of the six states appears in the fixture with its precedence.
- [ ] SUPERSEDED/DROPPED PRDs, `repo-setup.md` and partial REMOVED (`§`)
      bullets never change a row.

## Performance budget
- `features.sh` < 1 s on 100 PRDs and 40 specs (measured 65 ms).
- The file stays ≤60 rows and ≤2k tokens.
